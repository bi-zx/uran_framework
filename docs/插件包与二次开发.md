# 插件包与二次开发

## 使用安装后的公共 SDK

先按 README 构建并安装框架。最小扩展示例位于 `examples/extension`，包含 CMake 项目、实现、动态库 manifest 和包描述，能够在框架仓库之外独立编译。

```cmake
cmake_minimum_required(VERSION 3.16)
project(my_extension LANGUAGES CXX)
find_package(uran_plugin_api 2 REQUIRED CONFIG)
add_library(my_extension SHARED extension.cpp)
target_compile_features(my_extension PRIVATE cxx_std_17)
target_link_libraries(my_extension PRIVATE uran::uran_plugin_api)
install(TARGETS my_extension LIBRARY DESTINATION lib)
install(FILES plugin.json DESTINATION .)
```

插件继承 `Plugin`、`ProtocolPlugin` 或 `MessagePlugin`。从 PluginContext 保存所需的 shared_ptr 服务、身份与配置，避免保存 configure 参数的裸引用。状态字段登记与源码导出可直接参考 `examples/extension/extension.cpp`。

| 扩展方法 | 接入契约 |
| --- | --- |
| 通用后台扩展 | `Plugin` 生命周期，通过平台定时器和消息出口工作 |
| 接收通用消息 | `MessagePlugin` 声明类型，实现 `handle`，由目标设备/组件/实例/能力选择 |
| 新通信协议 | `ProtocolPlugin` 实现连接、断开、上行发送、下行回调 |
| 新操作系统/中间件 | 宿主注入 `PlatformServices`、`PluginLoader`、可选 `StateStorage` |

状态/消息/线程约束详见[架构说明](插件化架构说明.md)。API 2.0 当前提供 C++ 进程内插件；Python 是构建部署和管理客户端，没有内嵌 Python 插件执行器。

## 动态库 manifest：plugin.json

路径相对于 manifest 所在目录：

```json
{
  "schema_version": 1,
  "package": "example_extension",
  "version": "1.0.0",
  "api_version": "2.0",
  "plugins": [
    {"class_type": "example/Extension", "library": "lib/libexample_extension.so"}
  ]
}
```

原生库需导出 `extern "C" ... uran_plugin_export_v2()`，返回 ABI 2、class_type、create/destroy 函数。一个原生库对应一个导出类；包可以包含多个库。库、依赖和宿主需要匹配操作系统、架构及 C++ ABI。Loader 负责动态库生命周期，不能自行提前 dlclose。

包工具要求 library 使用相对路径，解析后仍位于该包安装前缀内，且文件存在。API 版本、包名、包版本需要与包描述一致。注册 manifest 验证发现信息，真正加载类时才检查 dlopen、导出 ABI 和实际插件描述。

## 下载包描述：uran-package.json

压缩包根目录必须含 `uran-package.json`，不能额外套一层目录。源码包示例：

```json
{
  "schema_version": 1,
  "package": "example_extension",
  "version": "1.0.0",
  "api_version": "2.0",
  "requires": {
    "os": ["Linux"],
    "arch": ["x86_64", "aarch64"],
    "commands": ["cmake", "c++"]
  },
  "build": {"kind": "cmake", "source": ".", "cmake_args": []},
  "plugin_manifest": "plugin.json"
}
```

`requires.os`/`arch` 是接受的候选清单，分别与 Python 的 `platform.system()`/`machine()` 比较，省略表示不作此项约束。`commands` 检查 PATH 中命令是否存在。它是目前可执行的环境声明格式，不会自动 apt/pip 安装，也不做 Python/系统依赖版本求解；需与云平台再统一发布协议。

CMake 源码构建执行 configure → build → install。`source` 相对于压缩包根目录；`cmake_args` 仅允许 `-D` 定义，不能覆盖工具管理的 `CMAKE_INSTALL_PREFIX` 和 `CMAKE_PREFIX_PATH`。`--sdk-prefix` 指向框架安装目录，依赖由 CMake 查找。框架 SDK 及插件私有动态依赖必须在运行环境可解析。

预编译包把 build 改为：

```json
{"kind": "prebuilt", "prefix": "prefix"}
```

示例目录：

```text
bundle/
├── uran-package.json
└── prefix/
    ├── plugin.json
    └── lib/libexample_extension.so
```

`plugin_manifest` 相对于最终安装前缀。包工具不接受归档符号链接、硬链接、绝对路径或 `..` 路径成员；预编译包应携带普通文件形式的库。源码包是会执行构建脚本的开发代码，原生插件也运行在宿主进程中，包来源需要可信；摘要用于确认内容，不替代发布者认证。

## 打包与应用

```bash
python3 scripts/uran_plugin.py pack examples/extension --output /tmp/extension.tar.gz
python3 scripts/uran_plugin.py install /tmp/extension.tar.gz \
  --store /tmp/uran-plugins --sdk-prefix "$PWD/install" \
  --runtime-socket /tmp/uran.sock --instance-id echo_extension \
  --device-id robot_001 --component-id extension --config '{}'
```

`pack` 输出归档路径与 SHA-256。安装 URI 支持本地路径、file URI、HTTPS；远程必须提供摘要：

```bash
python3 scripts/uran_plugin.py install https://plugins.example.com/extension.tar.gz \
  --sha256 '<发布方提供的64位十六进制摘要>' \
  --store /tmp/uran-plugins --sdk-prefix "$PWD/install" \
  --runtime-socket /tmp/uran.sock --instance-id echo_extension
```

仅 localhost HTTP 用于开发测试。`--class-type` 可指定包中的某个类，省略则选择第一个。`--jobs` 控制源码编译并发。`--config` 必须是 JSON 对象。省略 `--runtime-socket` 时只安装，随后可以手动 load。

安装采用临时 staging，全部验证/编译/安装完成后，移动至 `store/packages/<package>/<version>`，原子更新 `store/index.json`。同一版本不可覆盖；校验或构建失败不修改当前索引。索引只指向每个包最新安装的版本，旧版本文件仍保留。

在线应用向原生宿主发送 `load`，同时注册 manifest 并自动激活新实例。返回包含 `installed`、`manifest`、`index`、可选 `applied`；安装成功但运行时连接或激活失败时，`ok` 为 false，已安装版本保留用于诊断/重试。

升级相同类不会自动替换正在运行的实例：新建不同实例 ID 可以并存；替换原 ID 需要显式卸载旧实例再加载。已有实例继续持有旧动态库。安装索引切换不等于业务无损升级，也不会自动改写部署配置。

## 重新启动与装配

重启时从索引发现已安装类：

```bash
./install/bin/uran_runtime --plugin-index /tmp/uran-plugins/index.json \
  --config /tmp/extension-runtime.yaml --control-socket /tmp/uran.sock
```

对应 `/tmp/extension-runtime.yaml`：

```yaml
default_device_id: robot_001
routes:
  echo: example.echo
plugins:
  - instance_id: echo_extension
    component_id: extension
    class_type: example/Extension
    api_version: "2.0"
    enabled: true
    auto_activate: true
    priority: 10
    config: {}
```

也可通过 `--manifest` 指定清单，或在原生宿主 YAML 顶层用 `plugin_manifests` 列出相对 YAML 的清单路径。`--plugin-dir` 递归查找名为 `plugin.json` 的文件，不宜对包含多版本的整个 store 扫描，因为类映射可能冲突；版本安装场景使用 `--plugin-index`。

实例必填 `instance_id`、`component_id`、`class_type`，`device_id` 可由顶层默认值提供。可选 plugin_type/plugin_version/api_version 会与实现校验，API 即使省略也必须是当前 2.0。`config_file` 优先于内联 config；通过 start_file 启动时，插件私有文件路径相对于装配 YAML。可选 `route_scope` 是语义作用域；默认根据 runtime、设备、组件、实例生成。

## ROS 和其他平台扩展

中立插件的 ROS 导出参见 `src/uran_ros2_adapter/src/plugin_exports.cpp` 和 `plugin_description.xml`。外部 ROS 导出包需要链接中立插件，调用 `PLUGINLIB_EXPORT_CLASS`，并用 `pluginlib_export_plugin_description_file(uran_ros2_adapter ...)` 注册到适配器使用的基包索引；ROS Host 通过该索引发现类。

新中间件宿主负责把平台输入输出转成通用 envelope，并注入平台服务和 Loader。需要将下载后的插件用于新宿主时，包工具与宿主应约定管理接口；当前在线下载应用验证使用原生 Socket，不声称支持任意 ROS 包热安装。

平台实现应保证串行调度、时钟接口、可取消回调与加载器库生命周期，持久化后端应保证完整快照替换失败时旧快照保持不变。可以从应用主线程构造 `UranRuntime(loader, platform, storage)`，调用 start/load/dispatch 等接口，最后 stop 并销毁 Runtime，再关闭平台。
