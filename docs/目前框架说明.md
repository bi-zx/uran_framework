# 目前框架说明

## 当前状态

当前版本已从 C++/ROS 2 原型改为独立 C++17 核心、可替换平台适配器和 Python 插件工具。默认 `config/runtime.yaml` 是空装配。ROS 已退出通用 API 和核心依赖链，启用 `URAN_BUILD_ROS2` 才构建 ROS 宿主。

| 已实现 | 实际行为 |
| --- | --- |
| 独立 Runtime | 注入平台服务、Loader、Storage，无 ROS 可以启动、管理、停止 |
| 插件管理 | 描述/API/身份检查，配置、激活、停用、卸载，错误诊断及清理重试 |
| 多实例与能力发现 | 同一类多次实例化，按设备/组件分组，优先级选择，停用即撤销能力 |
| 消息分发 | 通用 MessagePlugin，按类型及目标身份/能力选择处理者 |
| 多协议网关 | 指定/主/备用协议顺序选择，上行失败回退，下行可信来源和绑定代次 |
| 状态管理 | 所有权隔离、类型验证、快照、内部订阅、可选真实文件持久化 |
| 受控执行 | 串行执行器、可取消定时器，实例停用回收任务，阻止框架回调内重入生命周期 |
| 配置装配 | YAML、插件私有配置文件、可选语义路由目录，启动失败清理候选会话 |
| 扩展安装 | 本地/HTTPS 包、SHA-256 校验、环境检查、CMake 编译、版本安装、在线加载激活 |
| 独立 SDK | 普通 CMake 安装与 find_package，仓库外示例仅依赖公共 API |
| ROS 适配 | pluginlib 后端，日志/时钟桥接、JSON Topic/Trigger Service 宿主和 bringup |

`loopback` 只回送消息；`example.echo` 只将输入 JSON 写入实例状态。这些示例验证机制，不代表任何实际机器人、云平台或通信协议已经接入。

## 原生宿主管理接口

`uran_runtime --help` 列出配置、manifest、插件目录、已安装索引、状态文件和管理 Socket 参数。宿主启动时先发现类，再按 YAML 创建实例；发现到类不等于自动实例化。

管理请求为一行 JSON，回应一般包含 `ok`、`message`，查询回应含 `result`。Socket 每次连接处理一个请求，默认仅当前用户可访问，限单条 1 MiB；它是本地受信任管理接口，不是远程云 API。回环下行事件输出到宿主 stdout，不混入 Socket 请求回应。

| `op` | 主要输入 | 效果 |
| --- | --- | --- |
| `status` | 无 | ready、运行时长、插件状态/健康/错误、能力和协议数、主协议 |
| `snapshot` | 无 | 当前状态 JSON |
| `classes` | 无 | Loader 已发现实现类 |
| `providers` | `capability`，可选 `device_id`、`component_id` | 可用能力提供者 |
| `load` | `plugin` 配置；可选 `manifest`、`replace` | 发现并创建实例，默认自动激活 |
| `activate` / `deactivate` / `unload` | `instance_id` | 变更实例生命周期 |
| `primary` | `instance_id` | 指定当前已激活协议为主协议 |
| `write` | `field`、`value`，可选 `persistent` | 以 `external.native` 写入状态 |
| `publish` | `message_type`、`payload`，可选 `correlation_id`、`urgent`、`preferred_protocol_instance` | 经协议网关上行 |
| `dispatch` | `message_type`、`payload`、可选 `target`/`correlation_id` | 从本地宿主投递通用下行消息 |
| `shutdown` | 无 | 停止 Runtime 并退出宿主 |

`replace: true` 仅允许替换类名到 manifest 动态库的映射；不会自动卸载同名实例或迁移其状态。热管理修改当前进程装配，不会重写启动 YAML。

## ROS 2 宿主接口

可通过 `ros2 run uran_ros2_adapter uran_runtime_node` 启动空宿主，或使用 README 中的 bringup 装配回环示例。参数为 `plugin_config`、`route_config`、`state_file`、`snapshot_period_ms`、`heartbeat_period_ms`。ROS Topic 名称由适配器的 `route_config` 指定，不进入核心 RouteCatalog。

| 默认地址 | 类型/方向 | 内容 |
| --- | --- | --- |
| `/uran/runtime/state_snapshot` | String 发布 | 状态 JSON 快照 |
| `/uran/runtime/heartbeat` | String 发布 | Runtime 诊断 JSON |
| `/uran/runtime/state_write` | String 订阅 | `field`、`value`、可选 `persistent`；来源固定 `external.ros2` |
| `/uran/runtime/state_report` | Trigger 服务 | 主动发布一次本地快照 |
| `/uran/runtime/uplink` | String 订阅 | `message_type`、`payload`、可选关联 ID/优先协议 |
| `/uran/runtime/downlink` | String 发布 | 未被插件消费的下行消息，含协议实例来源 |
| `/uran/runtime/management/request` | String 订阅 | `op`、实例或插件配置、可选 `correlation_id` |
| `/uran/runtime/management/reply` | String 发布 | 管理结果及对应 `correlation_id` |

ROS 管理支持 `load`、`activate`、`deactivate`、`unload`、`primary`、`status`。插件发现走 pluginlib XML/ament 索引；Python 安装工具在线应用走原生 Socket，二者没有隐式混用。String 通道是框架联调接口，尚未定义正式业务消息协议。

## 与原始 rebuild 的主要变化

原始版本的 `PluginContext` 暴露 ROS Node，核心依赖 rclcpp/pluginlib，并由 RuntimeNode 承担装配。当前 `UranRuntime` 是可嵌入库，ROS Node 留在 `uran_ros2_adapter`；原生宿主与 ROS 宿主复用同一核心。

原始版本只能用 ROS 构建和发现插件；现在普通 CMake 安装 SDK，原生 Loader 读取 manifest，Python 工具可以安装二进制包或编译源码包并应用。原先状态持久化标记没有对应独立后端，现在有原子快照接口和文件恢复。动态生命周期还会同步管理消息路由、能力、协议回调和调度任务。

此次不迁移 `uran_ws` 的具体业务实现，业务模块之后应作为扩展接入公共接口。旧 API 1.0 插件不能直接加载到 API 2.0 Runtime，需按[架构说明](插件化架构说明.md)迁移并重新编译。

## 与研发计划的对应关系

对照工作区《芯烛天巡2026年8月-11月研发计划.md》中“URAN 整体框架化改造”的工程要求：

| 计划要求 | 当前对应实现 | 尚需项目联调/验收 |
| --- | --- | --- |
| 独立 C++/Python 软件框架 | C++ 核心及 SDK、Python 包和管理工具，独立于 ROS 构建运行 | 目标设备工具链和系统版本验证 |
| ROS 作为可接入中间层 | 独立 ROS 适配器和 pluginlib 后端 | 具体平台/设备消息桥接 |
| 下载插件后自动应用 | URI + digest → 校验 → 编译/安装 → 原生宿主加载激活 | 实际插件库鉴权、发布和云端联调 |
| 类 requirements 的环境声明 | `uran-package.json` 声明 OS、架构、命令及构建方式 | 与云平台共同确定正式格式、依赖版本和自动补齐方案 |
| 二次开发技术路径 | 安装 SDK、外部源码示例、manifest 与生命周期契约 | 机械臂等实际扩展包及模型库接入 |
| 1–2 台设备测试 | 当前完成本机原生和 ROS 软件验证 | 尚未完成实机验收 |

因此，本次完成的是计划中框架基础设施的代码改造和本机验证。按键映射、运控/图传、自动任务、模型库、Agent、云端状态上报以及从零部署实机等后续任务，没有被本次空框架实现替代。

## 验证入口

- `ctest --test-dir build --output-on-failure`：核心组件、原生生命周期/调度/持久化、动态库、原生宿主、插件包链路与源码依赖边界。
- `URAN_BUILD_NATIVE=OFF` 独立构建及 CTest：核心不需要原生或 ROS 后端。
- `tests/test_plugin_install.py`：使用安装后的宿主和 SDK，执行本地二进制包应用、HTTP 本地仓库下载、外部源码编译、语义消息处理、重新发现；验证坏包/摘要/构建失败不破坏已安装索引，以及应用连接失败仍准确报告安装结果。
- `tests/test_ros2_host.py INSTALL_PREFIX`：安装后 ROS 宿主的 pluginlib、心跳、来源、管理、主备与快照验证，需已 source ROS 环境。

当前验证环境为 Linux、GCC 11、Python 3.10、ROS 2 Humble。跨操作系统、不同 C++ ABI、设备业务闭环和生产压力测试仍需在对应环境执行。
