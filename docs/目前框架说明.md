# URAN Core Framework 说明

## 1. 当前范围

当前工程是一套核心框架，不是完整产品实现。它把 URAN Core 需要的通用机制提取为独立 C++ 组件，并给具体协议、设备和业务留下扩展边界。

已经提供：

- `rclcpp` Runtime 节点。
- 配置快照管理器。
- 线程安全状态空间。
- 路由目录。
- 公共插件基类。
- 协议插件基类。
- `pluginlib` 插件管理器。
- 多协议网关和消息路由器。
- 插件生命周期和异常边界。
- 插件状态写权限与插件 ID 绑定。
- 回环协议示例插件。
- bringup 配置和 launch 文件。
- 配置、状态空间、路由、消息分发和协议网关单元测试。

当前未实现：

- 真实 MQTT/WebSocket 网络连接。
- 云端 JSON 与领域消息的正式编解码。
- 最终 URAN Message、Service 和 Action。
- 状态持久化后端。
- 运控、媒体、传感器和任务领域服务。
- 具体机器人设备适配。

### 与现有 `uran_core` 的对应关系

| 现有职责 | 新框架中的承载位置 |
|---|---|
| `core.yaml`、`network.yaml` 配置读取 | `ConfigManager` 与 bringup 配置 |
| `StateManager` 状态读写和变化通知 | `StateStore` 与 `ScopedStateAccess` |
| MQTT 连接和上下行 | `ProtocolPlugin`、`ProtocolGateway`；真实 MQTT 实现留给独立插件 |
| 按消息类型分发下行指令 | `MessageRouter`；具体业务处理留给后续领域模块 |
| 状态广播、心跳和主动上报 | `RuntimeNode` 的占位 ROS 2 端点和定时器 |
| 固定 Topic/Service 创建 | `RouteCatalog` 与 Runtime 装配层 |

该映射保留了原有核心功能的承载位置，但不复制原节点中的大段业务分支。

## 2. 运行关系

```text
uran_bringup
     │ 加载配置
     ▼
RuntimeNode
├── ConfigManager
├── StateStore
├── RouteCatalog
└── PluginManager
          │ pluginlib
          ▼
LoopbackProtocolPlugin
```

Runtime 与具体插件没有编译期实现依赖。`uran_bringup` 负责选择需要加载的插件，插件包通过 pluginlib 描述文件向 Runtime 声明实现类。

公共插件接口位于 `uran_plugin_api`。第三方插件只需依赖该包，不需要依赖 `uran_core_framework` 的具体实现。

## 3. 插件生命周期

```text
创建实例
   ↓
configure
   ↓
activate
   ↓
deactivate
   ↓
cleanup
   ↓
释放实例
```

PluginManager 在调用插件方法时不会持有内部管理锁，避免插件回调 Runtime 后形成锁重入。生命周期方法抛出的异常会被拦截并转换为状态结果。

批量加载插件时，如果某一插件配置或激活失败，PluginManager 会按相反顺序清理本次已经加载的插件。

## 4. 状态空间

StateStore 支持：

- 注册状态字段及所有者。
- 校验字段名称和 JSON 值。
- 控制已注册字段的写入来源。
- 扩展字段首次写入时绑定所有者。
- 生成保持 JSON 类型的状态快照。
- 订阅状态变化。
- 并发读取和独占写入。

PluginManager 为每个插件创建独立的 `ScopedStateAccess`。插件注册状态字段时可以省略所有者，
受控视图会自动绑定当前插件 ID；写入时若伪造其他来源，请求会被拒绝。

状态变化回调在状态锁外执行，因此回调可以再次读取 StateStore。
单个状态观察者抛出的异常会被隔离，不会改变已经提交的状态，也不会阻断其他观察者。

持久化标记目前只保存在状态元数据中，后续应通过 `StoragePlugin` 或独立持久化服务完成落盘。

## 5. 占位接口

RuntimeNode 当前使用 `std_msgs/msg/String` 提供状态写入、状态快照和心跳通道。这些通道只用于验证 Runtime 的装配关系，不应直接作为正式业务接口发布。

正式接口确定后，应增加独立接口包，并让 RuntimeNode 通过适配层调用 StateStore、PluginManager 等组件。核心组件不需要因 ROS 消息类型变化而重新设计。

## 6. 新增协议插件

协议插件需要：

1. 继承 `uran_plugin_api::ProtocolPlugin`。
2. 实现公共生命周期。
3. 实现 `connect()`、`disconnect()` 和 `publish()`。
4. 保存并调用 `DownlinkCallback`。
5. 使用 `PLUGINLIB_EXPORT_CLASS` 导出为 `uran_plugin_api::Plugin`。
6. 在 `plugin_description.xml` 中声明实现。
7. 在 bringup 插件配置中选择实现类。

网络库回调通常运行在独立线程。实现时应先把网络数据转换为不可变消息，再通过线程安全队列或 ROS 2 调度机制送入 Runtime，避免网络线程直接修改 Runtime 内部状态。
